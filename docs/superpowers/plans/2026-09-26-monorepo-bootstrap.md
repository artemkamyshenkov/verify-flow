# Monorepo Bootstrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a minimal pnpm monorepo in which a Vite React application and a Fastify TypeScript server install, run, test, type-check, and build from the repository root.

**Architecture:** The root owns workspace orchestration only, while `apps/web` and `apps/backend` own their dependencies and build configuration. The backend separates Fastify application construction from process startup so the health route can be tested without opening a network port.

**Tech Stack:** pnpm 12.6.0, React, TypeScript, Vite, Fastify, tsx, Node.js built-in test runner

**Spec:** `docs/superpowers/specs/2026-09-26-monorepo-bootstrap-design.md`

## Global Constraints

- Pin exactly `pnpm@12.6.0` in the root `packageManager` field.
- Keep all application dependencies inside their owning workspace.
- Do not add Turborepo, Nx, `packages/shared`, CORS, persistence, realtime, or verification-domain code.
- Keep one repository-level `pnpm-lock.yaml`.
- Both applications must run independently as well as through root orchestration.

## Review Focus

- Workspace discovery: `rtk pnpm --recursive list --depth -1` must include the `web` and `backend` packages after both apps exist; the root metadata is checked separately (Tasks 1 and 3).
- Package-manager drift: a Node assertion must confirm the root `packageManager` is exactly `pnpm@12.6.0` (Task 1).
- Backend contract: an injection test must confirm `GET /health` returns status 200 and `{ "status": "ok" }` (Task 2).
- Independent compilation: each workspace's own build and type-check commands must succeed before root orchestration is added (Tasks 1 and 2).
- Startup collision: a second backend process on port 3000 must report `EADDRINUSE` and exit non-zero rather than appearing healthy (Task 2).

---

## File Map

- `package.json`: private workspace root, pnpm version pin, and final orchestration scripts.
- `pnpm-workspace.yaml`: workspace package discovery under `apps/*`.
- `pnpm-lock.yaml`: single dependency lockfile generated from the root.
- `apps/web/package.json`: web-only dependencies and scripts.
- `apps/web/src/App.tsx`: minimal bootstrap screen with no backend integration.
- `apps/web/*`: Vite and TypeScript configuration generated by the React TypeScript template.
- `apps/backend/package.json`: backend-only dependencies and lifecycle scripts.
- `apps/backend/tsconfig.json`: strict Node-oriented TypeScript compilation to `dist`.
- `apps/backend/src/app.ts`: constructs and returns the Fastify application.
- `apps/backend/src/app.test.ts`: verifies the health route through `fastify.inject`.
- `apps/backend/src/server.ts`: starts the HTTP server and reports startup failure.
- `README.md`: prerequisites and root/workspace development commands.

- [ ] **Step 2: Verify the package-manager pin**

```bash
rtk node -e "const p=require('./package.json'); if(p.private!==true||p.packageManager!=='pnpm@12.6.0') process.exit(1)"
```

Expected: exit code 0.

- [ ] **Step 3: Scaffold and trim the web application**

Use the current Vite React TypeScript template under `apps/web`. Replace its demo UI and assets with a minimal `App` that renders the heading `Cross-device verification` and the text `Workspace bootstrap is running.` Preserve app-local generated tooling, but do not add dependencies beyond the template.

- [ ] **Step 4: Add an explicit web type-check script**

Add `typecheck` to `apps/web/package.json`, using the template's TypeScript project references without emitting output.

- [ ] **Step 5: Install once from the repository root**

Run `rtk pnpm install` at the repository root.

Expected: one root `pnpm-lock.yaml`, no nested lockfiles, and `rtk pnpm --filter web exec vite --version` succeeds.

- [ ] **Step 6: Verify the web workspace independently**

Run `rtk pnpm --filter web run typecheck` and `rtk pnpm --filter web run build`.

Expected: both commands exit 0 and Vite produces `apps/web/dist`.

- [ ] **Step 7: Commit the workspace and web scaffold**


### Task 2: Fastify Backend

**Files:**
- Create: `apps/backend/package.json`
- Create: `apps/backend/tsconfig.json`
- Create: `apps/backend/src/app.test.ts`
- Create: `apps/backend/src/app.ts`
- Create: `apps/backend/src/server.ts`
- Modify: `pnpm-lock.yaml`

**Interfaces:**
- Consumes: workspace discovery from Task 1.
- Produces: `buildApp(): FastifyInstance`, `GET /health`, and backend scripts `dev`, `build`, `start`, `typecheck`, and `test`.

- [ ] **Step 1: Define the backend package and strict TypeScript configuration**

Create an ESM package named `backend`. Add Fastify as a runtime dependency and TypeScript, tsx, and Node.js types as development dependencies. Configure Node-compatible ESM output from `src` to `dist` with strict type checking.

- [ ] **Step 2: Write the failing health-route test**

Create `apps/backend/src/app.test.ts`. Import `buildApp`, register `app.close()` through the test context's cleanup hook, call `app.inject({ method: 'GET', url: '/health' })`, and assert status 200 plus the exact JSON payload `{ status: 'ok' }`.

- [ ] **Step 3: Run the test to verify the missing implementation fails**

Run `rtk pnpm --filter backend run test`.

Expected: FAIL because `src/app.ts` or `buildApp` does not exist.

- [ ] **Step 4: Implement the Fastify application factory**

Create `buildApp(): FastifyInstance` in `apps/backend/src/app.ts`. Register only `GET /health`, returning `{ status: 'ok' }`.

- [ ] **Step 5: Run the health-route test**

Run `rtk pnpm --filter backend run test`.

Expected: one passing test with no network port opened.

- [ ] **Step 6: Implement the process entry point**

Create `apps/backend/src/server.ts`. Build the application, listen on port 3000 and host `127.0.0.1`, and set a non-zero process exit code after logging any startup error through Fastify's logger.

- [ ] **Step 7: Verify the backend independently**

Run `rtk pnpm --filter backend run typecheck`, `rtk pnpm --filter backend run test`, and `rtk pnpm --filter backend run build`. Start the compiled server, then start a second instance while port 3000 is occupied.

Expected: type-check, test, and build exit 0; compiled `dist/server.js` exists; the second process logs `EADDRINUSE` and exits non-zero.

- [ ] **Step 8: Commit the backend**

```bash
rtk git add apps/backend pnpm-lock.yaml
rtk git commit -m "chore: bootstrap Fastify backend"
```
